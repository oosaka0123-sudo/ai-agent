3AI競争テスト 第1回 ・ Claude Code版

スマホだけで
AI開発はどこまでできる？

Claude Code・Google Gemini / Jules・OpenAI Codexを比較し、調査から公開まで スマートフォン1台で完結できる範囲を検証しました。

2026年8月30日時点の公開情報にもとづく ・ 料金や無料枠は変更される可能性があります

結論を先に

「静的サイトを作ってGitHub Pagesで公開する」までは、スマホだけで完全に完結します。 Claude Code・Jules・Codexのいずれも、スマホのブラウザやアプリからチャットで指示を出すだけで、 クラウド上のAIがコードを書き、GitHubへPull Requestとして提案してくれます。 一方で、複雑な大規模改修・実機での細かいデバッグ・重い自動テストの実行は、 現時点ではPCがあった方が圧倒的に効率的です。詳しくは各章で解説します。

5項目別の詳しい解説

タップして開く

HTML / CSS / JavaScript開発

スマホでの開発は「自分でコードを一文字ずつ書く」のではなく、「AIに書かせて、結果を確認・微修正する」スタイルが現実的です。GitHubのWeb版編集機能はシンタックスハイライト付きのシンプルなエディタなので、小さな修正（文言変更、色の調整）ならスマホからでも直接編集できます。

  • 最初はindex.htmlとstyle.cssの2ファイルだけで始める
  • JavaScriptは必要になってから追加し、外部ライブラリへの依存はなるべく避ける
  • 1回の依頼で変更するファイルを1〜2個に絞ると、差分レビューが楽になる
PWA（Progressive Web App）開発

2026年時点でPWAをホーム画面に追加できるようにするには、主要ブラウザ共通で次の3つが必須です。

  • HTTPS（GitHub Pagesは標準でHTTPS配信）
  • Web App Manifest（name・icons・start_url・displayなどを記載したJSON）
  • Service Worker（オフライン対応やキャッシュ制御を行うスクリプト）

この3点セットのコード自体はAIに生成させられます。ただし、複数サイズのアイコン画像を用意する作業はスマホだと手間がかかりやすく、ここはPCの画像編集ソフトがあると効率的です。

{
  "name": "マイアプリ",
  "start_url": "./index.html",
  "display": "standalone",
  "theme_color": "#080b10",
  "icons": [{ "src": "icon-192.png", "sizes": "192x192", "type": "image/png" }]
}
API連携（公開API／秘密鍵が必要なAPI）

天気・ニュース・地図など「キー不要、または公開キーでよいAPI」は、スマホから作った静的サイトにfetch()を書くだけで連携できます。

一方、決済・生成AI・DBアクセスなど「秘密鍵が必要なAPI」は、HTML/CSS/JavaScriptだけで動く静的サイトのブラウザ側コードには絶対に書けません（誰でも見られてしまうため）。この場合は、GitHub Actionsやサーバーレス関数など「鍵を安全に保管できる場所」を別途用意する設計が必要です。この設計自体はAIに相談しながら決められますが、実際に鍵を安全な場所（GitHub Secretsなど）に登録する操作は、慎重に確認しながら行ってください。

AIエージェント開発・自動化

Claude Codeの「Routines」は、プロンプト・接続するリポジトリ・使えるツールをあらかじめ登録しておき、スケジュール（毎日・毎週など）やAPI呼び出し、GitHubのWebhookイベントをきっかけに自動実行できる機能です（2026年4月から研究プレビューとして有料プランに提供）。「毎晩バグ報告を確認して修正案のPRを作る」といった無人運用が可能になります。

Gemini・JulesやOpenAI Codexも、GitHub Actionsと組み合わせることで「Issueが立ったら自動でタスクを割り当てる」といった自動化を組めますが、Claude CodeのRoutinesのような「AI自身がスケジュールを持つ」専用機能は、本記事執筆時点ではClaude Codeが先行しています。

複数AIを同じGitHubリポジトリで使う方法

複数のAIエージェントが同じリポジトリで衝突せず作業するための、よく使われる工夫です。

  • 共通ルールファイルを置く: AGENTS.mdのような、どのAIも参照する共通指示ファイルを用意し、ブランチ運用・秘密情報の扱いなどを明文化する
  • 担当ファイル・担当ディレクトリを分ける: 同じファイルを複数のAIが同時に編集しないようにする
  • 作業ブランチを分ける: 各AIが自分専用のブランチで作業し、Pull Request経由で統合する
  • 他のAIの成果物を書き換えない: 比較・競争のような文脈では、それぞれが独立して作業したことに意味があるため、他AIのファイルには触れない運用にする
ブランチ・Pull Request運用

AIエージェント（人間も同様）は、mainブランチを直接書き換えるのではなく、作業ブランチを作ってPull Requestを提案する、という流れを徹底するのが安全です。理由は次の3つです。

  • 差分（変更点だけ）を確認できるので、意図しない変更に気づきやすい
  • 問題があればPull Requestを閉じるだけで済み、本番を壊さない
  • 複数AI・複数人が同時に作業しても、それぞれ独立したブランチなら衝突しにくい

6PCが必要になる場面 / スマホだけで完結する範囲

📱 スマホだけで完結できる

  • アイデア出し・要件整理（AIとの壁打ち）
  • 1〜数ページの静的サイトの作成・公開
  • 文言修正・配色変更などの軽微な編集
  • GitHub上でのPull Requestレビュー・マージ
  • GitHub Pagesの公開設定
  • 公開APIを使った簡単な連携

💻 PCがあった方がよい

  • 数十ファイルにまたがる大規模な設計変更
  • 複雑な差分レビュー（画面の狭さがボトルネックになる）
  • 自動テスト・CIログの詳細な調査
  • 複数サイズの画像・アイコン素材の一括加工
  • 実機に近い環境でのパフォーマンス計測
  • 秘密鍵を扱うサーバー設計・デプロイの検証

9まとめと注意事項

要点

  • 「調査→設計→コーディング→GitHub保存→公開」までは、3つのAIいずれを使ってもスマホだけで完結できる
  • PWA・API連携は「コードを書く」段階はスマホで可能。ただし秘密鍵の扱いや画像素材の加工はPCが楽
  • 大規模な改修・詳細なデバッグ・自動テストのログ調査は、現時点ではPCの方が効率的
  • 複数AIの併用は、共通ルールファイル・担当分割・ブランチ運用で衝突を防げる
  • 料金・無料枠・機能名は変わりやすいため、契約前に必ず公式情報を確認する
