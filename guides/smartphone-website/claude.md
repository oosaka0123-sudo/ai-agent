## この方法の特徴

Claude Codeは「チャットで質問して、自分でコードを書き写す」ツールではなく、
**リポジトリを直接読み書きしてコマンドを実行できる実装エージェント**です。
`claude.ai/code`（Claude Code on the web）を使えば、PCのターミナルを一切開かずに
スマートフォンのブラウザだけから「指示 → 実装 → テスト → GitHubへコミット・push」
まで一気通貫で任せられます。

この方法の一番の特徴は、**AIが「提案」ではなく「作業」を完了させる**ことです。
このリポジトリ自身の `AGENTS.md`（自律実行ルール）に書かれているとおり、
Claude Codeは明確な指示を受けたら、実装 → 動作確認 → 自己レビュー → 修正 →
再テスト → 記録 → コミット → push まで、途中で細かい確認を挟まずに完了させます。
つまりこのガイド自体が「スマホだけでClaude Codeにホームページを作らせた実例」です。
本文はスマホから見ても崩れないよう、この方法で実際に検証しながら書いています。

## 必要なサービス

- **GitHubアカウント**（無料） — コードの保存場所（SSOT: Single Source of Truth）。
- **Claude Codeが使える環境** — `claude.ai/code`（ブラウザ版）、または
  Claude Codeのモバイルアプリ／Claude系アプリからClaude Codeセッションを開ける環境。
  スマホのブラウザだけでも動作します。
- **GitHub Pages**（GitHubに含まれる無料機能） — 完成したHTML/CSSをそのまま
  インターネットに公開する仕組み。追加のサーバー契約は不要です。
- （任意）**独自ドメイン** — 使わなくても `https://ユーザー名.github.io/リポジトリ名/`
  という形のURLで公開できます。

## スマホでの手順

1. スマホのブラウザでGitHubにログインし、新しいリポジトリを作成する（後述）。
2. スマホのブラウザで `claude.ai/code` を開き、そのリポジトリを開く/接続する。
3. Claude Codeに日本語で「どんなサイトを作りたいか」を伝える
   （例:「自己紹介ページを作って。名前・経歴・連絡先を載せて、ダークテーマで」）。
4. Claude Codeが実装内容を確認できる形で返してくるので、スマホの画面で
   スクロールしながら確認する（コードを手で書く必要はない）。
5. 「スマホ幅（390px前後）で崩れていないか確認して」「見出しの色を変えて」
   のように、気になった点をそのまま日本語で伝えて修正させる。
6. 問題がなければ「コミットしてpushして」と伝える（このリポジトリの運用では、
   さらに「Pull Requestを作って」まで一括で依頼できる）。
7. GitHub Pagesが有効なら、数十秒〜数分後に公開URLへスマホでアクセスして確認する。

PCのターミナル操作・ローカル環境構築（Node.jsのインストールなど）は一切発生しません。

## GitHubリポジトリ作成

1. スマホのブラウザでGitHubにサインインする（未登録なら無料でアカウント作成する）。
2. 右上の「+」→「New repository」をタップする。
3. リポジトリ名を入力する（例: `my-first-website`）。
4. 公開設定は「Public」を選ぶ（GitHub Pagesを無料枠で使う場合はPublicが簡単）。
5. 「Add a README file」にチェックを入れて作成する
   （空リポジトリよりも、最初の1ファイルがある状態の方がAIが状況を把握しやすい）。

このリポジトリでは、複数のAIが同じGitHubリポジトリを「共通の記憶」として使う運用
（`README.md` のオンボーディング手順、`AGENTS.md` の自律実行ルール）を採用しています。
個人サイト1つを作るだけならここまでの仕組みは不要ですが、
「AIとの会話が途切れても、GitHub上の記録を見れば続きから再開できる」という考え方は
個人開発でもそのまま役立ちます。

## AIとの接続

1. `claude.ai/code` にスマホのブラウザでアクセスし、サインインする。
2. GitHub連携（GitHub連携の許可画面）が出たら許可し、対象のリポジトリを選ぶ。
3. 接続できたら、Claude Codeがそのリポジトリのファイル一覧・内容を読める状態になる。
4. あとはチャット欄に日本語で指示するだけで、Claude Codeがファイルの作成・編集・
   コマンド実行（テストなど）・GitHubへのコミット/pushまで行う。

Claude Codeは「何を」「なぜ」変更したいかが明確な指示ほど得意です。
「かっこよくして」だけよりも、「トップに大きな見出し、下に自己紹介、
連絡先はメールアドレスへのリンクにして」のように、具体的に伝えるとやり直しが減ります。

## HTML/CSS作成

Claude Codeにコードを書かせる場合、スマホ側では以下だけ意識すれば十分です。

- **何のページか**（自己紹介・ポートフォリオ・お知らせページ など）
- **載せたい情報**（見出し・本文・画像・リンク・連絡先 など）
- **雰囲気**（明るい/暗い、カジュアル/かっちり、参考にしたい既存サイトがあれば伝える）
- **スマホでの見やすさ**（このサイト自体がそうであるように、まずスマホ幅を基準にする
  「モバイルファースト」を指示に含めると、AIが最初からスマホ最適化したCSSを書く）

コード自体（HTML/CSS/JavaScriptの文法）を理解している必要はありません。
Claude Codeが生成した内容をスマホのブラウザでプレビューし、
「ここの余白を広げて」「文字が小さいので大きくして」のように見た目ベースで
フィードバックすれば、Claude Codeが該当箇所を特定して直します。

## GitHubへの保存

Claude Codeに「コミットして」「pushして」と伝えるだけで、
変更内容の要約を含んだコミットメッセージが自動生成され、GitHub上の
リポジトリへ反映されます。手元でGitコマンドを打つ必要はありません。

このリポジトリでの標準的な運用（`docs/DEVELOPMENT.md` 参照）では、

- `main` ブランチには直接pushせず、作業用ブランチ + Pull Requestを経由する
- 1つの変更目的ごとにコミットを分ける
- 秘密情報（パスワードやAPIキーなど）は絶対にコミットしない

というルールを敷いています。個人サイト単体でここまで厳密にする必要はありませんが、
「あとから見返せる形で記録が残る」「間違えても`main`が壊れない」という安心感は、
スマホだけで作業する場合に特に効いてきます。Pull Requestを作るところまで
Claude Codeに任せることもでき、その場合はGitHub側の画面でスマホから
「Merge」ボタンを押すだけで公開用ブランチに取り込めます。

## 公開方法

GitHub Pagesを使うと、追加のサーバー契約なしにそのまま公開できます。

1. GitHubのリポジトリ画面で「Settings」→「Pages」を開く。
2. 「Build and deployment」の「Source」を、
   - 単純なHTML/CSSのみの構成なら「Deploy from a branch」→ `main` ブランチ
   - このリポジトリのようにビルド・同期処理を挟む構成なら「GitHub Actions」
   を選ぶ（Claude Codeにどちらが必要か確認しながら選ぶとよい）。
3. 数十秒〜数分待つと、`https://ユーザー名.github.io/リポジトリ名/` で公開される。
4. 以後は、Claude Codeに変更を依頼して`main`へ反映されるたびに自動で再公開される。

このサイト（MY DEVELOPMENT ARCHIVE）自体もこの仕組み（`.github/workflows/pages.yml`）
で公開されています。

## 初心者が迷いやすい点

- **「保存」と「公開」は別の操作**: GitHubへコミットしただけではインターネットには
  公開されない。GitHub Pagesの設定（上記）が必要。
- **反映に少し時間がかかる**: pushしてから公開URLに反映されるまで、数十秒〜数分の
  タイムラグがある。すぐに変わらなくても慌てず少し待ってから再読み込みする。
- **Publicリポジトリは中身が誰でも見える**: 個人情報や秘密の値をそのままコードに
  書き込むと、リポジトリを見た人全員に見えてしまう。連絡先メールアドレスなど
  公開してよい情報だけを載せる。
- **「Claude」と「Claude Code」は別物**: 通常のClaude（チャット）はコードを
  提案するだけで、実際にリポジトリへ書き込む・コマンドを実行する機能は持たない。
  スマホだけで「実装からGitHubへの反映まで」を完結させたい場合は、
  Claude Codeのようにリポジトリへの読み書きができるエージェントを使う必要がある。
- **通信が不安定だと処理が途中で切れることがある**: 電波の悪い場所で長い作業を
  依頼すると、応答が途中で止まることがある。作業を細かい単位に分けて
  依頼すると影響を受けにくい。

## メリット

- PCを持ち歩かなくても、電車移動中や外出先からサイトを更新できる。
- コードの文法を知らなくても、日本語の指示だけで実装が進む。
- GitHubに保存されるため、変更履歴が自動的に残り、失敗しても前の状態に戻せる。
- 実装だけでなく、動作確認・修正・記録までをAIに一括で任せられるため、
  「作って終わり」ではなく「動くところまで」到達しやすい。
- 無料のGitHub Pagesで公開でき、追加のサーバー費用が発生しない。

## デメリット

- 複雑な機能（会員登録・決済・大規模なデータベース連携など）は、
  スマホの小さい画面での確認作業自体が負担になりやすい。
- AIの提案をそのまま受け入れ続けると、なぜそう動くのかを自分では説明できない
  「ブラックボックス化」が起きやすい。気になった部分は都度、AIに理由を確認するとよい。
- 画面が小さいため、細かいレイアウト崩れ（文字の折り返し位置など）に
  気づきにくい場合がある。
- 長時間の作業や大きな変更ほど、通信状況や表示の見づらさの影響を受けやすい。

## 費用

GitHubアカウントの作成、パブリックリポジトリの利用、GitHub Pagesでの公開は
いずれも無料です。追加でかかる可能性があるのは、独自ドメインを取得する場合の
ドメイン費用や、Claude Codeを含むAIサービス側の利用プラン（無料枠か有料プランかは
サービス側の提供状況によって変わる）です。具体的な料金・無料枠の範囲は変動するため、
このガイドでは金額を断定せず、利用前に各サービスの公式サイトで最新情報を
確認することをおすすめします。

## PCが必要か

**必須ではありません。** 指示・実装確認・GitHubの操作・公開設定まで、
すべてスマホのブラウザだけで完結できます。実際にこのガイド自身も、
スマホ幅（390px前後）での見え方を基準に、Claude Codeとの日本語でのやり取りを
通じて作成・確認しています。

ただし、長文の指示を何度も入力する、細部の見た目を1ピクセル単位で調整する、
といった作業はPC・タブレットの大きな画面とキーボードがあった方が快適です。
「最初の公開まではスマホだけ、細かい調整だけ後でPCから」という使い方もできます。

## 最終的に何ができるか

- 自己紹介・ポートフォリオ・お知らせ・簡単な作品集など、静的なHTML/CSSサイトを
  スマホだけで企画から公開まで完結できる。
- GitHubに変更履歴が残るため、何度でも安全にやり直し・改善ができる。
- GitHub Pagesで無料公開でき、公開後もスマホからClaude Codeに追加の変更を
  依頼し続けられる（「お知らせを1件追加して」「写真を差し替えて」など）。
- このリポジトリのように、複数のAIエージェントがGitHubを介して並行作業する
  発展形（開発記録の自動蓄積、複数AIによる比較検証など）にも、同じ「スマホ +
  Claude Code + GitHub」の土台をそのまま拡張していける。
