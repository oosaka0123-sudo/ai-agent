## この方法の特徴

**【結論】** PCは一切不要。スマホのブラウザのみで、AIエージェントによる自律的な調査からコーディング、GitHubへの保存、そして世界への公開（GitHub Pages）まで、すべてのAI開発フローを完結させる最先端のアプローチです。

### スマホ完結AI開発の3大特徴

*   **🚀 超軽量スタート:** 専用アプリや重いIDE（開発環境）のインストール不要。必要なのはブラウザだけ。
*   **🤖 AIチーム駆動:** Claude Code、Gemini/Jules、OpenAI Codexを並行稼働させ、各AIの強みを活かした共同開発が可能。
*   **🔄 完全自律実行:** AIがGitHubを「共通記憶」として扱い、リポジトリの読み書き、ブランチ作成、PR発行までを自律的に行う。

## 必要なサービス

以下のサービスのアカウント（すべて無料枠あり）を用意するだけです。

1.  **GitHub アカウント**: コードの保存・バージョン管理・公開基盤
2.  **AIプロバイダ**: Anthropic, Google, OpenAI等のAPIまたはチャット画面
3.  **GitHub Pages**: 作ったものを無料で即座にWeb公開

## スマホでの手順

### 実践フロー：調査から公開まで

*   **1. 調査・設計 (AI)**: AIに作りたいものを伝え、構成を提案させる
*   **2. リポジトリ準備 (GitHub)**: スマホのブラウザでGitHubを開き、空のリポジトリを作成
*   **3. 実装依頼 (AI)**: AIに「専用ブランチを作ってコードを書き、PRを出して」と指示
*   **4. レビュー・修正 (AI自律)**: AIが自分でコードを書き、テストし、修正まで行う
*   **5. マージ・公開 (GitHub)**: スマホでPRを承認・マージし、GitHub Pagesで自動公開

## GitHubリポジトリ作成

### スマホ画面での操作

*   スマホのブラウザで `github.com` にログイン。
*   右上の「+」アイコンをタップし、「New repository」を選択。
*   Repository name に名前（例: `ai-mobile-app`）を入力。
*   「Add a README file」にチェックを入れる（重要：AIがリポジトリを操作しやすくなる）。
*   「Create repository」をタップ。

## AIとの接続

### 複数AIを同じGitHubで使う方法

AI間で直接の会話履歴は共有できません。そのため、**GitHubリポジトリ自体を記憶装置として使います。**

*   リポジトリのルートに `AGENTS.md` を作成し、AI共通のルール（「直接mainにpushしない」「テストしてからPRを出す」等）を記載します。
*   各AI（Claude, Gemini, Codex）に「まずリポジトリの `AGENTS.md` と `README.md` を読んでから作業して」と指示します。
*   これにより、どのAIに頼んでも一貫したルールで開発が継続します。

## GitHubへの保存

### ブランチ / PR運用

*   **ブランチ作成:** AI（指示による） - ◎ 自動
*   **ファイル作成/編集:** AI（指示による） - ◎ 自動
*   **Pull Request作成:** AI（指示による） - ◎ 自動
*   **PRのレビュー・承認:** 人間（スマホブラウザ） - △ 画面が狭いが見れる
*   **マージ:** 人間（スマホブラウザ） - ○ ボタンタップのみ

## 公開方法

GitHub Pagesを使えば、サーバー構築不要で無料公開できます。

*   スマホのブラウザで対象リポジトリを開く。
*   「Settings」タブ → 左メニュー「Pages」を開く。
*   「Source」を `Deploy from a branch` にし、ブランチを `main`（または `gh-pages`）に設定して「Save」。
*   数分後、`https://ユーザー名.github.io/リポジトリ名/` で公開完了！

## 初心者が迷いやすい点

*   **Q: エラーが出たらどうする？** A: エラー画面をスクショしてAIに貼り付け、「このエラーを直して再度PRを出して」と指示するだけです。自分でコードを直す必要はありません。
*   **Q: AIが途中で止まったら？** A: 「続けて」「次はどうする？」と促します。プロンプトで「途中で確認せず最後まで自律実行して」と事前指示しておくのがコツです。
*   **Q: 秘密情報（APIキー等）はどうする？** A: リポジトリの `.env` に書き（絶対にコミットしない！）、AIには「APIキーは .env から読み込む実装にして」と指示します。

*   移動中やベッドの上など、**いつでもどこでも開発が進められる**。
*   AIが書いたコードを読むことで、**自然とプログラミングの学習になる**。

## デメリット

*   スマホの画面サイズでは、複雑なコードの全体像や差分（Diff）を俯瞰しづらい。
*   ブラウザの「検証ツール（DevTools）」が使えないため、細かなデザイン調整の指示が難しい。
*   AIのコンテキスト制限（一度に読めるコード量）を超えると、プロジェクト全体の把握が難しくなる。
