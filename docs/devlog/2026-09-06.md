- プロジェクト: AIエージェント

### 今日やったこと

- ユーザーから「Claude / Claude Cowork / Claude Code / GitHub / MCP / API / Google系
  サービス等を確認し、最も合理的で保守しやすいAI開発環境を設計・実装してほしい」という
  依頼を受け、まず現状を棚卸しした。
  - `ai-agent`（本リポジトリ）: `AGENTS.md` を中心に3AI（Claude Code / Gemini・Jules /
    Codex）共通のブランチ運用・自律実行ルール・自己評価ルール・開発記録ルールが既に整備済み。
    `mcp_server/` に Google Media MCP・Steel Browser MCP という2つの共有Remote HTTP MCPが
    実装済みで、least-privilege（Inbound認証とアップストリーム認証情報の分離）パターンも
    確立済みだった。`docs/GPT_GITHUB_CONTROL.md` / `docs/MULTI_PROJECT_ORCHESTRATION.md` に
    ChatGPTのPM/オーケストレーション役割も既に定義されていた。
  - `oosaka0123-sudo/ai-master`（依頼文中でMaster Repositoryとして指定されたリポジトリ）:
    実在を確認し、clone・read-write接続を確認した。README/AGENTS/CONNECT/PROJECTS/DECISIONSの
    最小5ファイル構成を採用済みで、ADR-002/ADR-003で「上位ルールファイルを増やしすぎない」
    「MASTER.md等の重複ファイルを作らない」ことを明示的に決定済み。ADR-012では
    「製品名と役割の固定マッピングをMasterの不変ルールにしない、Capability-based Routingを
    使う」ことも明示的に決定済みだった。
- 依頼文で提示されていた `agents/` `mcp/` `docs/architecture/` `templates/` `security/` 等の
  ディレクトリ構成をそのまま `ai-master` へ機械的に作ると、上記ADR-002/003/012の既存の
  設計判断（および `AGENTS.md` の GLOBAL MUST NOT 8「AGENTS.md/DECISIONS.mdの根幹方針を
  ユーザーの明示的な方針変更なしに変更しない」）と衝突すると判断した。依頼文にも
  「既存構造がある場合は壊さず、現在の構造を確認してから統合してください」とあったため、
  `ai-master` 側は変更せず、Claude製品ファミリーの役割分担・MCP分類という**本題の内容**を
  `ai-agent`（Projectローカル）側に実装する方針にした
  （`ai-master/AGENTS.md` の「Projectローカル運用ルールがMasterのDEFAULTをそのProject内だけ
  上書きできる」という優先順位ルールに合致する）。

### 困ったこと・判断したこと

- 依頼文が提案する「Master Repositoryへ`agents/` `mcp/` `docs/` `templates/` `security/`の
  重量級ディレクトリを作る」という具体的な指示と、`ai-master`が既に持つ
  「最小5ファイル構成」「製品名を役割に固定しない」という明示的なADR判断が矛盾していた。
  秘密情報の誤コミットや不可逆操作ではないため作業停止はせず、`ai-master`の既存ガバナンスを
  尊重して変更を加えず、実質的な価値（役割分担の明確化・MCP分類・Secret方針・引き継ぎ様式）は

- 複数リポジトリにまたがるAI運用基盤を設計する際は、依頼文の具体的な構成案をそのまま実装するより、
  対象リポジトリが既に持つ設計判断（ADR等）を先に確認し、根幹方針の変更が必要な場合は
  リポジトリ側のガバナンスルール（ここでは「明示的なユーザー方針変更が必要」というルール）に
  従うべきである。

### 次にやること

  `ai-master/CONNECT.md` へ実アクセスの結果を追記する（このセッションでは未確認のため
  今回は追記していない）。

## PR #39をmergeable状態まで仕上げ、Mobile First / Cloud Firstを正式化・棚卸し

- プロジェクト: AIエージェント

### 今日やったこと

1. 前段の作業（Claude製品ファミリーの役割分担とMCP分類）についてユーザー承認を受け、
   `oosaka0123-sudo/ai-agent` の [PR #39](https://github.com/oosaka0123-sudo/ai-agent/pull/39)
   を作成した。CI（シークレットスキャン・pytest）は初回から成功。Copilotの自動レビューで

   解決し、`mergeable_state: clean` まで仕上げた。
2. ユーザーから新しい共通方針「Mobile First / Cloud First」（原則としてスマートフォンだけで
   指示→AI作業→GitHub変更→テスト→承認→デプロイを完結できる環境を目指す）が明示された。
   `oosaka0123-sudo/ai-master` の既存 `DECISIONS.md` / `AGENTS.md` / `CONNECT.md` を確認し、

   追記した（`oosaka0123-sudo/ai-master`
   [PR #27](https://github.com/oosaka0123-sudo/ai-master/pull/27)）。
3. Google Media MCPの既知BLOCKER（Cloud RunホストへのCONNECTがagent proxyで403拒否）を
   本セッション（Claude Code cloud実行環境）から `curl .../healthz` で実際に再現・再確認し、
   `ai-master/CONNECT.md` を更新した。あわせてClaude Code→GitHubの検証範囲に
   `ai-master` 自体を追加した。
4. Claude / Claude Code / Cowork / GitHub / Google Media MCP / Steel Browser MCP等について、
   スマホ完結を阻害するローカル依存箇所を棚卸しし、`docs/MOBILE_CLOUD_FIRST.md` に

5. アクセス可能な範囲の実装として、`ai-agent` リポジトリ直下に `.mcp.json` を新規追加し、
   `google-media` エントリ（URLは公開情報、トークンは環境変数参照のみ）を設定した。
   Steel Browser MCPは未デプロイ、Google Media MCPへの接続はegress policyで依然ブロック
   されているため、これらは人間の環境設定作業が必要な項目として明記し、全体の作業は
   停止せず記録・報告する方針とした。
