# 2026-09-05 の開発記録

## Steel Cloud Browser MCP を共有 Remote HTTP MCP として追加

- プロジェクト: ai-agent

### 今日やったこと

- PC電源OFFでもChatGPT / Claude / Gemini等のAIクライアントから共通のクラウドブラウザを利用できるように、Steel Cloud Browser を共有 Remote HTTP MCP として実装した。
- 5つの最小ツール (`create_session`, `navigate`, `extract`, `screenshot`, `release_session`) を実装した。
- Inbound Auth (`STEEL_BROWSER_MCP_TOKEN`) と Upstream Auth (`STEEL_API_KEY`) を完全に分離し、MCPクライアントへ Steel API Key が露出しない安全設計にした。
- SSRF対策として URL Scheme チェック、localhost / metadata IP / プライベートIPレンジの拒否機構 (`url_validator.py`) を実装した。
- セッションTTL / アイドルタイムアウト自動クリーンアップおよびアプリ終了時一括リリース機能 (`session_manager.py`) を実装した。
- `/healthz` および `/readyz` 正常性チェックエンドポイントと structured JSON ログ出力を追加した。
- unit / integration test 25件を追加し、108件全テストが正常通過することを確認した。
- ドキュメント `docs/STEEL_BROWSER_MCP.md` を作成し、構成・仕様・Human Gate手順を記録した。

### 困ったこと・判断したこと

- Google Media MCP との責務分離を守るため、既存の `mcp_server/app.py` を変更せず、独立したパッケージ `mcp_server/steel_browser/` とエントリーポイント `mcp_server/steel_app.py` を作成した。
- クライアントへの Steel API Key 漏洩を防ぐため、Inbound Auth と Upstream Auth を完全に分離した。

### 学んだこと

- Remote HTTP MCP において、アップストリームサードパーティAPIキーをプロキシサーバー側で保持し、インバウンドBearer認証で保護することで、クライアントの認証分離と安全なクラウドブラウザ共有が実現できる。
